Build a team of synthetic employees with Claude Code

Twelve steps, real screenshots. You will create a GitHub repository, give Claude research to learn from, turn it into a team of expert AI agents with their own knowledge, brains and personalities, put them on a website you can share, then build a software team of your own.

  • No coding needed
  • About 1 hour
  • Live demo: experts21.netlify.app
  • Example: 26 agents for a Miami coffee shop

1

Create a GitHub repository called Experts21

The repository is the filing cabinet your expert team lives in. Everything Claude builds gets saved here.

  1. Go to your GitHub page (mine is github.com/fenago) and click Repositories.
  2. Click the green New button.
  1. Type Experts21 as the repository name. GitHub shows a green tick when the name is free.
  1. Switch Add README to On.
  2. Click Create repository. That is all.

Good to know: GitHub does not allow spaces in names, so use Experts21 (no space). If you type "Experts 21" it becomes "Experts-21".

2

Connect Claude Code to your repository

Claude Code needs to know which repository to work in.

Before you start: the GitHub connector must already be connected. In Claude, open Customize → Connectors and make sure GitHub Integration has a check mark. If it does not, click it and connect your GitHub account first.

  1. Go to claude.ai/code and click New.
  2. Under the message box, click the repository name and search for Experts21. Click fenago/Experts21 (yours will show your own GitHub name).
  1. Click the model name (bottom right) and choose Opus 5.5. Make sure Effort says Medium. Do not use Fable.
3

Give your experts context: research the topic

Your agents are only as smart as what they know. This step builds their shared library. Pick any topic you like; I used opening a coffee shop in Miami.

Paste this into Claude Code
The next step is to do some research on opening a specialty coffee shop in Miami, Florida: the market, target customers, competitors, startup and operating costs, permits and licenses, staffing, marketing, and the biggest risks. Put the results of that research inside a docs folder (one markdown file per topic plus a README index), and push the docs folder and research out to the main branch on GitHub. This is context for a team of expert agents we will build next.

Claude searches the web, writes one file per topic and saves them in a docs folder. Mine took about 4 minutes.

Good to know: Have your own documents (a business plan, a contract, a spreadsheet)? Click the + in the message box to attach them and say "add these to the docs folder too."

Check it worked: Open your repository on GitHub and click the docs folder. You should see the research files.

4

Ask who should be on your expert team

A good consultant surrounds themselves with specialists. Claude decides which roles you need, and which skills they will use.

Paste this into Claude Code
If I were a consultant on this project and I wanted to surround myself with experts (experts in the business domain, the technical domain, operations, finance, legal, marketing, and so on), give me a list of all of the experts I would need to advise me on this project. Use the research in the docs folder. I am going to turn each of these roles into an agent, so for each role give me a one-line job description. Then define the skills those agents will need. Remember that one skill can be shared by several agents, so show which agents use each skill. Save the list to docs/expert-roster.md and push it to the main branch.

Good to know: A skill is a reusable method, like "analyze a lease" or "build a break-even model." One skill can be shared by many agents, so you write it once.

5

Build the agents and skills

This turns the roster into real, working agents that live inside your project, plus an orchestrator to run the team and a meta agent that can build new agents.

Paste this into Claude Code
Read the official Claude Code documentation on subagents (https://code.claude.com/docs/en/sub-agents) and skills (https://code.claude.com/docs/en/skills). Then build every agent from docs/expert-roster.md as a project subagent in .claude/agents/, and build every skill as a project skill in .claude/skills/<skill-name>/SKILL.md, wiring each agent to the skills it uses. In addition to the roster, build two more agents: an orchestrator agent that takes any question, decides which experts to bring in, has them work together, and returns one combined answer; and a meta agent that can create new agents and skills and improve existing ones. Aim for 10 to 50 agents in total. Everything must live inside this project. Add a CLAUDE.md that explains the team and how to use it. Push everything to the main branch on GitHub.

Check it worked: On GitHub, open .claude → agents. You should see one file per agent, including orchestrator and the meta agent (mine is called agent-builder).

6

Get prompts that make the experts work together

This is your expert counsel. You can ask one expert, or ask the whole team and let the orchestrator coordinate.

Paste this into Claude Code
Give me three or four example prompts I can use that would trigger several of these agents to work together and coordinate one answer through the orchestrator. Also show me how to ask one specific agent a question, and how to ask the whole team a question. Save them to docs/how-to-talk-to-your-experts.md and push to main.

Ask one expert

Type @ and pick the agent, then your question:

@agent-permitting-specialist What permits does a 20-seat cafe need, and in what order?

Ask the whole team

Start with the orchestrator:

@agent-orchestrator Should we sign this lease? Bring in the experts and tell me what to negotiate.
7

Give every agent a knowledge folder, a brain and a personality

The knowledge folder is where you feed each expert its own documents. The brain is the model it runs on: Opus is the deepest thinker, Sonnet is the all-rounder, Haiku is the fastest.

Paste this into Claude Code
Create a knowledge folder for each agent (knowledge/<agent-name>/ with a short README explaining what documents belong there) and update each agent so it always reads its knowledge folder before answering. Also pick the right brain for each agent: set the model in each agent's file (opus for deep strategy, legal and finance judgment; sonnet for most specialist work; haiku for fast, simple lookups) and explain the choice in a table in docs/agent-brains.md. Give every agent a distinct personality: a first name, a voice, and a working style, and list them in the same table. Push everything to main.

Check it worked: On GitHub, open docs/agent-brains.md to see which model each agent uses and why, and open the knowledge folder to see one folder per agent.

8

Test an agent with your own documents

Prove each expert reads its knowledge folder and answers the way you expect, in its own voice.

  1. On GitHub, open knowledge → the agent you want to teach (I used real-estate-advisor). Click Add file → Upload files (or Create new file to paste text).
  1. Click Commit changes and keep Commit directly to the main branch selected.
  1. Back in Claude Code, ask that agent a question about the document:
Paste this, changing the agent and question
First pull the latest from main. I added a document to the knowledge folder for the real-estate-advisor. @agent-real-estate-advisor Using that document, should we sign this Brickell lease as written? What are the top three things to negotiate? Tell me which documents you used.

Good to know: Repeat for each agent you care about. If an answer is off, tell Claude what you expected and ask it to fix that agent.

9

Take one agent into your Claude account Optional

Package an expert as a skill so you can consult it from any Claude chat, any time.

Paste this into Claude Code
Package the real-estate-advisor agent (Victor) as a standalone Claude skill I can upload to my Claude account under Customize > Skills: a folder named victor-real-estate-advisor with a SKILL.md (name and description in the frontmatter) that contains Victor's personality, instructions, his skills, and his knowledge files plus the research he relies on. Zip it as exports/victor-real-estate-advisor.zip and push it to main.
  1. On GitHub, open exports → victor-real-estate-advisor.zip and click the download button.
  1. In Claude, open Customize → Skills → Add → Upload skill and choose the zip.
  2. In any chat, ask "Ask Victor whether this lease is fair" and attach your lease.

Good to know: Everything inside the zip goes into your Claude account, including the knowledge files. Check for anything private first.

10

Call your agent from code with the Claude Agent SDK Optional

Make an expert available outside Claude, so other programs can ask it questions.

Paste this into Claude Code
Using the Claude Agent SDK documentation (https://code.claude.com/docs/en/agent-sdk/overview and https://code.claude.com/docs/en/agent-sdk/subagents), build a small Node.js script in sdk/ that loads Victor (the real-estate-advisor agent) from .claude/agents/ together with his knowledge folder, asks him a question passed on the command line, and prints his answer. Include a README with the exact commands to install, set ANTHROPIC_API_KEY, and run it. Test it here if an API key is available; if not, test that it loads the agent correctly and tell me. Push to main.

To run it on your own computer (needs Node.js and an Anthropic API key from platform.claude.com):

Mac / Linux

cd sdk
npm install
export ANTHROPIC_API_KEY="your-key"
npm run check
node ask-victor.mjs "Should we sign the Brickell lease as written?"

Windows PowerShell

cd sdk
npm install
$env:ANTHROPIC_API_KEY = "your-key"
npm run check
node ask-victor.mjs "Should we sign the Brickell lease as written?"

Good to know: npm run check proves Victor loads without spending anything. Each real question is billed to your API key. To use a different expert, change the agent name at the top of the script.

11

Build the web app and deploy it on Netlify

This is what you submit: a web page where you can talk to any expert, or the whole team, from any browser.

Part A: have Claude build the app

Paste this into Claude Code
Build a React web app in a folder called web/ that lets me talk to my experts: a sidebar listing every agent with its name, personality and model, a chat window, and an "Ask the whole team" option that routes the question through the orchestrator. Read the agents and their knowledge folders from this repo at build time. The Claude API call must run in a Netlify Function so my API key is never in the browser; the key comes from an ANTHROPIC_API_KEY environment variable in Netlify. Add a netlify.toml at the root of the repo so Netlify builds it with no extra settings, and a README with step-by-step deploy instructions. Test that it builds, then push everything to main.

Part B: deploy on Netlify

  1. Go to app.netlify.com (sign up free with your GitHub account if you need to). Click Add new project → Import an existing project, then GitHub.
  1. Search for Experts21 and click it.
  1. Give the project a name (this becomes your web address). Leave every build setting as it is: Claude's netlify.toml fills them in.
  1. Scroll down to Environment variables → Add environment variables → Add key/value pairs. Key: ANTHROPIC_API_KEY. Value: your Anthropic API key (create one at platform.claude.com → API keys). Tick Contains secret values.
  2. Optional: add a second variable APP_PASSWORD so only people with the password can use your app (and spend your API credit).
  3. Click Deploy.
  1. Wait about a minute for the deploy to finish, then click your new web address.

Part C: try it

Try mine: experts21.netlify.app. Please keep it to one or two short questions. Dr. Lee pays for every answer, so don't go crazy with it.

Good to know: Every time you push to main (for example, adding a document to a knowledge folder), Netlify rebuilds the site on its own, so your experts stay up to date.

What to submit: your Netlify link (for example https://experts21.netlify.app) and your GitHub repository link.

12

Your turn: build a software team that builds real software

Now do it again for real. Start fresh with something you are actually working on, but this time your agents don't just advise you. They build the software.

Repeat steps 1 to 3 with a brand-new repository (for example MyAppTeam). In step 3, research your real problem and attach your own documents: notes, spreadsheets, screenshots of the process you do by hand today. Then, instead of step 4's consultant roster, use the prompt below so the agents are a software team.

Pick one of these and actually build it

1. Booking and intake app

Customers book a time, fill in an intake form and get a confirmation email. You see every booking on one page. Good for any service business, office hours or consultations.

Agents: product manager, UX designer, front-end developer, back-end developer, QA tester, security reviewer, DevOps

2. Turn your spreadsheet into a real app

Take a spreadsheet you update by hand every week (sales, inventory, leads, student grades) and turn it into a web app with a form, a dashboard and charts.

Agents: product manager, data modeler, front-end developer, chart and dashboard developer, QA tester, DevOps

3. Proposal or quote generator

Answer a few questions about a client and get a branded proposal or quote as a web page and PDF, with your pricing rules built in.

Agents: product manager, pricing analyst, copywriter, front-end developer, PDF/export developer, QA tester

4. Internal knowledge chatbot

A chat page that answers your team's questions from your own policies, FAQs and manuals, and says which document the answer came from.

Agents: product manager, knowledge curator, prompt engineer, front-end developer, back-end developer, security reviewer, QA tester

5. Customer follow-up tracker

A simple CRM: add leads, log every call or email, get a "who to follow up with today" list, and see your pipeline by stage.

Agents: product manager, workflow designer, front-end developer, back-end developer, data modeler, QA tester, DevOps

The software-team prompt (use after your research step)
I'm going to build real software, and I want a team of agents that builds it for me. Using the research and documents in the docs folder, give me the list of agents a professional software team would need for this project (for example: product manager, UX designer, software architect, front-end developer, back-end developer, QA tester, security reviewer, DevOps). Include an orchestrator agent that runs the team and a meta agent that can add new agents. For each agent, define its skills (skills can be shared), give it a knowledge folder, pick the right model, and give it a personality. Read the official docs first (https://code.claude.com/docs/en/sub-agents and https://code.claude.com/docs/en/skills), build every agent in .claude/agents/ and every skill in .claude/skills/, add a CLAUDE.md that explains the team, and push everything to main.
Then have the team build version 1
@agent-orchestrator Have the team build version 1 of the app described in the docs folder. The product manager writes the requirements first, the architect picks a simple stack that deploys on Netlify, the developers build it, the QA tester tests every feature, and the security reviewer checks that no API keys or private data are exposed. Run the experts in parallel: launch every expert whose inputs are ready at the same time (and run the peer reviews in parallel too), and only wait when one expert needs another's output. Add a Resources page to the app that lists every link the project relies on (the official documentation for each library, the GitHub repository and the step-by-step guide) and link to it from the app's header or footer. Add a netlify.toml and a README with deploy steps, then push everything to main and tell me what was built and what is left for version 2.

Good to know: Work in small rounds. After version 1 is live, open the site, write down what is wrong or missing, and send it back: "@agent-orchestrator Here is my feedback on version 1: ... Have the team fix it, test it, and push to main." Netlify redeploys on its own.

Your assignment: pick at least one idea (or your own real project), build the agent team, have the agents build and deploy version 1, and submit your Netlify link and GitHub repository link.
