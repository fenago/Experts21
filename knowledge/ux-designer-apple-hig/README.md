# Knowledge folder — Wren, Apple-Style UX Designer (Human Interface Guidelines)

`ux-designer-apple-hig` reads **every file in this folder, including `docs/` and `examples/`, before answering any question**, and studies the `examples/` before any review or design work. Put documents here that only this expert needs, or that it needs more than the rest of the team.

## What's here

| File | What it is |
|---|---|
| `notes-official-sources.md` | Notes and verbatim quotes from Apple's HIG (Materials, Color, Typography, Layout, Accessibility, Tab bars, Sidebars), Adopting Liquid Glass, Apple's fonts license, and MDN, with links and coverage notes |
| `docs/navigation-tab-bars-and-sidebars-reference.md` | One-page reference: when to use a tab bar vs. a sidebar, their rules, and a web checklist |
| `docs/accessibility-and-states-reference.md` | One-page reference: the numbers to check, system settings → CSS media queries, and the states every screen needs |
| `examples/sample-ranked-usability-review.md` | **What good looks like:** a ranked usability review with evidence, severity, fixes, and effort (hypothetical screen) |
| `examples/states-good-vs-bad.md` | **Good vs. bad** empty, loading, error, and setup states with exact microcopy and HTML |

## What belongs here

- Usability test notes and recordings summaries (no personal data)
- Feedback from the consultant or Dr. Lee about what's confusing
- Analytics exports about where people get stuck
- Updated notes when Apple changes the HIG (with links and dates)

## What doesn't belong here

- Research for the whole team → `docs/`
- Reviews and outputs → `docs/ux-review.md` or `deliverables/`
- Passwords, account numbers, or sensitive personal data — this folder is pushed to GitHub

## How to add a document

Drop the file in this folder (or `docs/` / `examples/`), name it `YYYY-MM-DD-short-topic.ext`, and add a line at the top saying where it came from and when.
